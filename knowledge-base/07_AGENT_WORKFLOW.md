## 一、三層分工（Decision #003/#016）

| Agent | 角色 | 職責 | 禁止 |
|:------|:-----|:-----|:-----|
| **CEO** | 決策者 | 決定方向、核准、最終驗收 | — |
| **Hermes** | PM | 規劃、拆解、派工、追蹤、驗收、回報、排除阻塞 | 不決定技術方案細節、不直接生圖 |
| **Codex** | 執行者 | 所有程式開發、生圖、Git、部署、測試、圖片資源 | 不寫教材文案 |
| **WorkBuddy** | 執行者 | 教材內容、電子書、文案、案例整理、營運文件、PDF | 不碰程式 |

## 二、Workflow（CEO Agent 管理框架）

```
分析 → 拆解 → 分工 → 追蹤 → 驗收 → 回報 CEO
```

1. Hermes 分析需求，拆成可獨立驗收的小任務
2. 依專長派工（Codex 技術 / WorkBuddy 內容）
3. 持續追蹤，Agent 閒置 10 分鐘即改派
4. 每完成即驗收，不合格退回
5. 回報 CEO（含 % / 已完成 / 阻塞 / 下一步）

## 三、派工規則

- **交辦 Codex**：只給目標 + 驗收標準 + 期限，技術細節由 Codex 自主
- **交辦 WorkBuddy**：只給需求 + 格式 + 標準
- **真人操作事項**：一次集中列給 CEO
- **影響程式/DB/變數/Dashboard/Git commit/merge/push**：皆需 CEO 核准（CEO 標準指令⑤）

## 四、知識庫讀取/更新規則（本資料夾）

1. **派任務前**：Hermes 須要求執行 Agent 先讀取相關 `knowledge-base/*.md`
2. **CEO 出新決策時**：Hermes 先更新 `08_DECISION_LOG.md` 及相關主文件，再派發後續任務
3. **所有 Agent** 以本知識庫為唯一事實來源，衝突時標記、不自行決定

## 五、品質回報原則

- **先展示、後驗收**：完成可視化成果（截圖/HTML/PDF/PNG/網址）→ 提供 → 等 CEO 驗收 → 才算完成（「沒有可視成果，就等於沒有完成」）
- **失敗要標示**：模型/工具失敗標「執行失敗」，不得回報已「完成」
- 固定回報格式：% / 已完成 / 阻塞 / 下一步 / 是否需要 CEO 決策
