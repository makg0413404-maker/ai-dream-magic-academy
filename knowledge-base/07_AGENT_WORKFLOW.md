## 一、三層分工（Decision #003/#016）

| Agent | 角色 | 職責 | 禁止 |
|:------|:-----|:-----|:-----|
| **CEO** | 決策者 | 決定方向、核准、最終驗收 | — |
| **Hermes** | PM | 規劃、拆解、派工、追蹤、驗收、回報、排除阻塞 | 不決定技術方案細節、不直接生圖 |

### 驗收分工（CEO 確認）
- **WorkBuddy**：文字、文案、電子書內容 校對與驗收
- **Codex**：圖片、UI、**圖片內文字**、版面設計 校對與驗收
- **注意**：圖片內的文字（如封面 Slogan 嵌在圖片中）**不得交由 WorkBuddy 驗證**，屬 Codex 職責。若圖片內文字有誤，派 Codex 修正圖片，非修改 HTML。
| **Codex** | 執行者 | 所有程式開發、生圖、Git、部署、測試、圖片資源 | 不寫教材文案 |
| **WorkBuddy** | 執行者 | 教材內容、電子書、文案、案例整理、營運文件、PDF | 不碰程式 |

### 長期分工戰略（CEO 2026-07-31，記錄但不施工）

```
Hermes      專案管理｜任務分派｜驗收｜Roadmap 管理
Codex       PWA 網站｜資料庫｜API｜後台｜AI 引擎整合
WorkBuddy   各產業研究｜魔法咒語內容建立｜電子書｜教學教材｜行銷內容
品牌分析Agent(未來) 分析新店家｜建立品牌知識庫｜更新品牌資料
```

**原則**：目前仍以 8/3 MVP 為最高優先，不新增施工項目。此分工為未來長期方向。

## 二、Workflow（CEO Agent 管理框架）

```
分析 → 拆解 → 分工 → 追蹤 → 驗收 → 回報 CEO
```

1. Hermes 分析需求，拆成可獨立驗收的小任務
2. 依專長派工（Codex 技術 / WorkBuddy 內容）
3. 持續追蹤，Agent 閒置 10 分鐘即改派
4. 每完成即驗收，不合格退回
5. 回報 CEO（含 % / 已完成 / 阻塞 / 下一步）

## 三、派工規則

- **交辦 Codex**：只給目標 + 驗收標準 + 期限，技術細節由 Codex 自主
- **交辦 WorkBuddy**：只給需求 + 格式 + 標準
- **真人操作事項**：一次集中列給 CEO
- **影響程式/DB/變數/Dashboard/Git commit/merge/push**：皆需 CEO 核准（CEO 標準指令⑤）

## 四、知識庫讀取/更新規則（本資料夾）

1. **派任務前**：Hermes 須要求執行 Agent 先讀取相關 `knowledge-base/*.md`
2. **CEO 出新決策時**：Hermes 先更新 `08_DECISION_LOG.md` 及相關主文件，再派發後續任務
3. **所有 Agent** 以本知識庫為唯一事實來源，衝突時標記、不自行決定

## 五、品質回報原則

- **先展示、後驗收**：完成可視化成果（截圖/HTML/PDF/PNG/網址）→ 提供 → 等 CEO 驗收 → 才算完成（「沒有可視成果，就等於沒有完成」）
- **Vision QA（永久流程，P0，2026-07-31 生效）**：所有網站/電子書/圖片設計交付，必須同時提供：
  1. 桌機版截圖
  2. 手機版截圖
  3. Vision QA 檢查清單（A視覺 / B UI / C 功能）
  4. 發現問題與修正紀錄
  未完成以上項目，不得回報「完成」。
  - **流程為永久，不依賴單一模型**：即使目前視覺模型無法讀圖，仍以實際截圖進行人工＋AI交叉驗收（人手看圖 + 可用工具驗證）；後續評估導入具備圖片理解能力的 Vision 模型/Agent 提升自動化。
  - Vision QA 檢查項目：
    - A 視覺：Hero 使用最新核准主視覺？誤用舊素材？Logo/品牌色/字體一致？符合品牌規範？
    - B UI：桌機/手機截圖、文字是否被遮擋、按鈕正常顯示、間距合理
    - C 功能：QR 可掃描、連結 HTTP 200、無 404/500、CTA 導向正確
- **失敗要標示**：模型/工具失敗標「執行失敗」，不得回報已「完成」
- 固定回報格式：% / 已完成 / 阻塞 / 下一步 / 是否需要 CEO 決策
