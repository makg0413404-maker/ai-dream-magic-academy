## 一、MVP 開發目標

### 要解決的核心問題

| # | 問題 | 影響 |
|:-:|:-----|:-----|
| 1 | 網站是純靜態的，表單資料無法保存 | 講座報名、聯絡諮詢等商業線索全部流失 |
| 2 | 沒有會員系統 | 無法累積學員、無法區分免費與付費 |
| 3 | 沒有後台管理 | 更新課程／文章需要修改程式碼 |
| 4 | 品牌已完整但沒有套用到程式碼 | 現有網站尚未套用 Brand Bible 視覺規範 |
| 5 | 尚未部署上線 | 無法展示、無法招生、無法營運 |

### MVP 2.0 核心目標

> **在 4 個 Sprint（約 2 週）內，完成一個可上線、可展示、可收集報名資料的營運版本。**

### P0 — 必須完成

| 功能 | 理由 |
|:----|:------|
| 部署上線（Vercel） | 沒有上線＝網站不存在 |
| 講座報名表單可真正儲存 | 8 月 3 日講座需要報名功能 |
| 品牌視覺套用（Brand Bible） | 品牌已定稿，網站必須反映品牌 |
| 首頁 Hero 更新（軌跡引導版） | 品牌首頁必須呈現完整品牌形象 |
| 修復斷裂連結 | 忘記密碼連結等錯誤影響信賴感 |

### P1 — 重要

| 功能 | 理由 |
|:----|:------|
| 會員註冊／登入（Email） | 報名後學員需要查詢記錄 |
| 會員中心（基本資料＋報名記錄） | 會員基本體驗 |
| 聯絡表單可真正儲存 | 商業線索不漏接 |
| 提示詞中心（靜態 MVP 版） | 品牌差異化功能：AI 提示詞平台 |

### P2 — 之後再做

| 功能 | 理由 |
|:----|:------|
| Google OAuth 登入 | 可延後，Email 登入先上線 |
| 金流串接 | MVP 階段還不收費 |
| 課程 LMS | 需要更多課程內容才能上線 |
| AI 生成功能 | 屬於第二階段產品 |
| PWA 完整支援 | MVP 先以網站為主 |

## 二、網站架構

### 頁面清單（MVP 2.0）

```
/                              首頁 — 全新 Hero（軌跡引導）+ 品牌視覺
├── /courses                   課程中心 — 課程列表（品牌卡片）
│   └── /courses/[slug]        課程詳情（品牌佈局）
├── /prompts                   提示詞中心（全新頁面）
├── /events                    講座活動 — 講座列表
│   └── /events/[slug]         講座詳情 + 可儲存的報名表單
├── /blog                      教學文章 — 文章列表
│   └── /blog/[slug]           文章內容
├── /gallery                   AI 圖片案例
├── /about                     關於我們
├── /faq                       常見問題（全新頁面）
├── /contact                   聯絡我們 + 可儲存的聯絡表單
├── /auth
│   ├── /auth/login            會員登入（Email）
│   ├── /auth/register         會員註冊
│   └── /auth/forgot-password  忘記密碼（新增，修復斷裂連結）
└── /dashboard                 會員中心（全新頁面）
    ├── /dashboard             個人資料
    ├── /dashboard/my-events   我的報名
    └── /dashboard/settings    帳號設定
```

### 頁面關聯

```
首頁 → 課程中心 → 課程詳情
首頁 → 講座列表 → 講座詳情 → 報名（需登入？可先不強制）
首頁 → 提示詞中心
首頁 → 教學文章
首頁 → AI 案例
頁尾 → 關於我們／常見問題／聯絡我們

登入 → 會員中心 → 我的報名
註冊 → 會員中心
```

### 後端架構決策

**建議使用 Supabase（Free Tier），因為：**

| 需求 | Supabase 方案 |
|:----|:-------------|
| Email 註冊／登入 | ✅ Supabase Auth（內建） |
| 報名資料儲存 | ✅ Supabase DB（event_registrations 表） |
| 聯絡表單儲存 | ✅ Supabase DB（contact_messages 表） |
| 會員資料 | ✅ Supabase Auth 自動建立 profiles |
| 費用 | ✅ Free Tier（50,000 月活躍用戶，足夠 MVP） |
| 部署 | ✅ 不需自建後端，不需伺服器 |

## 四、開發 Roadmap

### Sprint 1：基礎建設＋品牌套用（預計 3-4 天）

| 項目 | 說明 |
|:----|:------|
| **開發內容** | ① Supabase 專案建立＋Schema 執行 ② GitHub push ③ Vercel 部署 ④ 品牌視覺套用（色彩/字體/按鈕/卡片） ⑤ 首頁 Hero 更新（軌跡引導版） ⑥ 修復斷裂連結 |
| **驗收標準** | 網站可在 Vercel 開啟、品牌色彩正確、Hero 動畫正常、無斷裂連結 |
| **預估工時** | Codex 約 6-8 小時 |
| **風險** | git push 認證問題（需預留解決時間） |

### Sprint 2：後端串接＋表單儲存（預計 3-4 天）

| 項目 | 說明 |
|:----|:------|
| **開發內容** | ① Supabase client 整合 ② 講座報名表單串接 Supabase ③ 聯絡表單串接 Supabase ④ 剩餘名額顯示 ⑤ 防止重複報名 |
| **驗收標準** | 報名資料可寫入 Supabase、聯絡訊息可寫入、剩餘名額正確更新 |
| **預估工時** | Codex 約 6-8 小時 |
| **風險** | Supabase RLS policy 設定需注意安全性 |

### Sprint 3：會員系統（預計 3-4 天）

| 項目 | 說明 |
|:----|:------|
| **開發內容** | ① Supabase Auth 串接 ② 註冊頁面（Email） ③ 登入頁面 ④ 忘記密碼頁面 ⑤ 會員中心（個人資料） ⑥ 會員中心（我的報名） ⑦ middleware 路由保護 |
| **驗收標準** | 可註冊、可登入、可編輯個人資料、可查看報名記錄、未登入無法進入 /dashboard |
| **預估工時** | Codex 約 8-10 小時 |
| **風險** | Email 驗證流程需確認 Supabase 設定正確 |

### Sprint 4：內容頁面＋上線準備（預計 2-3 天）

| 項目 | 說明 |
|:----|:------|
| **開發內容** | ① 提示詞中心（靜態 MVP 版） ② 常見問題頁面 ③ 全站 RWD 測試 ④ 全站 SEO 檢查 ⑤ 最終部署驗證 |

## 開發原則提醒

| 原則 | 說明 |
|:----|:------|
| **最快上線** | 優先完成可展示、可收費、可讓會員使用的功能 |
| **不過度設計** | 不做完美主義的 UI 調整，先求功能完整 |
| **品牌一致** | 所有新功能都要符合 Brand Bible |
| **AI 是工具，人才是主角** | 文案主詞是「你」和「我們」 |
| **熟齡友善** | 字體 ≥18px、對比度 ≥4.5:1、按鈕 ≥44px |
