# AI 圓夢魔法學院 · 教材內容驗收規範 V1.0

> 版本：V1.0
> 建立者：Hermes（PM）
> 適用範圍：Knowledge Base 所有教材、講義、咒語案例
> 原則：教材是核心資產，PDF/網站/DOCX 皆為輸出形式

---

## 1. 品牌一致性（權重 25%）

| 項目 | 標準 | 不符即退件 |
|:-----|:-----|:-----------|
| 品牌角色 | 使用「小圓（魔法學徒）」與「小靈（紫龍精靈）」 | ❌ 若使用其它虛擬角色 |
| 品牌符號 | ✦ 四角星（嚴禁五角星 ⭐） | ❌ 若出現五角星 |
| 品牌色 | 藍 #4F7CFF / 紫 #7C3AED / 金 #F4C542（僅文字提及，非設計） | — |
| 世界觀用語 | 使用「魔法咒語」「魔法學院」「咒語」「召喚」「魔法之門」 | ❌ 若使用「Prompt」「提示詞工程」「AI 模型」等術語 |
| 禁用詞 | 不使用：五角星、AI 模型、機器學習、深度學習、神經網路、參數 | ❌ 若出現上述詞彙 |
| 語氣 | 溫暖陪伴、不說教、不說「你竟然不會」 | ❌ 若語氣像教科書或技術文件 |

## 2. 熟齡閱讀體驗（權重 25%）

| 項目 | 標準 | 不符即退件 |
|:-----|:-----|:-----------|
| 句子長度 | 每句 ≤ 25 字（平均 15–20 字） | ❌ 若出現超過 40 字的長句 |
| 段落長度 | 每段 ≤ 5 行（手機螢幕） | ❌ 若出現超過 10 行的段落 |
| 術語說明 | 任何專業詞彙首次出現時附一句白話解釋 | ❌ 若出現未說明的術語 |
| 數字使用 | 使用台灣慣用數字格式（如 1,000 → 1,000 / 1萬） | — |
| 稱呼 | 使用「你」和「我們」，不使用「使用者」「用戶」 | ❌ 若出現「使用者應注意」 |

## 3. 手機閱讀友善（權重 15%）

| 項目 | 標準 | 不符即退件 |
|:-----|:-----|:-----------|
| 標題層級 | H1 → H2 → H3，不跳級 | ❌ 若出現 H1 直接跳到 H4 |
| 步驟格式 | 使用有序清單（1. 2. 3.）而非長段落描述 | ❌ 若步驟藏在段落中 |
| 程式碼區塊 | 魔法咒語使用 ```copy 標示（可複製） | ❌ 若咒語放在段落文字中 |
| 表格 | 表格欄位 ≤ 3 欄，否則改用清單 | ❌ 若出現 5 欄以上表格 |
| 圖片預留 | 截圖位置使用 `<!-- 截圖：XXX -->` 註解 | — |

## 4. Markdown 規範（權重 15%）

| 項目 | 標準 |
|:-----|:-----|
| 檔案編碼 | UTF-8（無 BOM） |
| 換行 | LF（Unix style） |
| 標題 | 章節標題 = H1，區段標題 = H2，子區段 = H3 |
| 連結格式 | `[顯示文字](相對路徑/)`（專案內）或完整 URL（外部） |
| 圖片路徑 | `![alt](assets/filename.png)` |
| 中英混排 | 中文與英文之間加空格（如「AI 工具」非「AI工具」） |
| 檔案命名 | 全小寫 + 連字號（如 `how-to-use-chatgpt.md`，非 `HowToUseChatGPT.md`） |

## 5. PDF 輸出一致性（權重 10%）

| 項目 | 標準 |
|:-----|:-----|
| 來源 | PDF 必須從 Markdown 產生（不可手動編輯 PDF） |
| 工具 | 優先使用 Pandoc 或 markdown-pdf |
| 版本標示 | PDF 頁尾包含「版本號 + 日期」 |
| 目錄 | 超過 10 頁的 PDF 必須有目錄頁 |

## 6. 未來網站整合性（權重 5%）

| 項目 | 標準 |
|:-----|:-----|
| 獨立頁面 | 每個章節 index.md 可獨立成頁 |
| 咒語複製 | 每個魔法咒語區塊使用 ```copy 標示，未來可直接掛接 clipboard JS |
| 導航鏈結 | 每個 index.md 結尾有「下一步」連結至下一章 |
| 元資料預留 | 每份文件第一行可加入 `<!-- status: draft|review|published -->` |

## 7. 魔法咒語格式一致性（權重 5%）

| 項目 | 標準 |
|:-----|:-----|
| 咒語結構 | 角色 → 任務 → 風格 → 細節 → 輸出格式（五段） |
| 變數標示 | 使用 `{{變數名稱}}`（雙大括弧） |
| 複製區塊 | 完整咒語包在 ```copy 區塊內 |
| 範例 | 每咒語附一組「輸入範例 → 輸出範例」 |
| 備援 | 若變數未填，顯示「（請補充）」|

## 8. 驗收流程

```
教材撰寫（WorkBuddy）
    │
    ▼
自我檢查（WorkBuddy 依本規範過一遍）
    │
    ▼
Hermes 驗收
    │
    ├── 🟢 通過 → 標記 published → Codex commit
    │
    └── 🔴 退件 → 附註違反項目 → WorkBuddy 修改
```

**退件條件**（任一項不符即退件，不需全部檢查）：

1. ❌ 出現五角星 ⭐
2. ❌ 出現未說明的技術術語
3. ❌ 語氣像教科書/技術文件（非溫暖陪伴）
4. ❌ 步驟藏在段落中（非有序清單）
5. ❌ 咒語格式沒有使用 ```copy 區塊
