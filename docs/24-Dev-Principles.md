# AI 圓夢魔法學院 · 永久開發原則

> 本文件記錄所有不可違反的開發原則。任何 Agent（Hermes / Codex）在進行開發決策前，都必須先檢視本文件。

---

## 原則一：熟齡友善第一優先

**任何新功能都必須回答一個問題：**

> **「這個功能能不能讓熟齡學員用手機在 3 分鐘內完成？」**

若答案是否定的，該功能必須重新設計或暫緩。

### 具體標準

| 維度 | 標準 |
|:-----|:-----|
| 操作步驟 | 最多 3 個點擊完成核心任務 |
| 文字輸入 | 盡量減少，優先用選擇代替輸入 |
| 字體大小 | 內文 ≥ 18px，不可小於 14px |
| 表單欄位 | 必要欄位 ≤ 5 個 |
| 錯誤訊息 | 清楚說明如何解決，不顯示技術錯誤碼 |
| 載入時間 | 首屏 ≤ 3 秒 |

### 禁止事項

- ❌ 增加操作步驟而不說明理由
- ❌ 使用專業術語而不提供解釋
- ❌ 在小螢幕隱藏重要功能
- ❌ 要求使用者學習複雜流程

---

## 原則二：小步提交（Small Commits）

每完成一個 Task 即建立一個 Git Commit，不得累積大量修改。

---

## 原則三：每 Task 必須驗收

每個 Task 完成後必須執行：
- `npm run build`
- `npm run lint`
- TypeScript 型別檢查
- 功能測試

全部 PASS 才能進下一個 Task。

---

## 原則四：錯誤不累積

若 Build 或測試失敗，立即修復，不得帶著 Error 繼續開發。

---

## 原則五：品牌一致性

所有設計決策必須符合 Brand Bible V1.0，尤其是：
- 色彩系統（魔法藍 #4F7CFF / 魔法紫 #7C3AED / 金色 #F4C542）
- 字體系統（Noto Sans TC + Inter）
- 「AI 是工具，人才是主角」

---

## 原則六：會員中心極簡

會員中心目前只保留：
- AI 圖片教學
- AI 影片教學
- 提示詞工具
- 個人資料
- 活動報名

**不得新增工作流教學功能。**

---

## 原則七：Media 統一 Schema

`media_items` 必須支援：
- `image`（圖片）
- `youtube`（YouTube 影片）

保留 `sort_order` 欄位，未來方便首頁排序。

---

## 原則八：Payment 架構優先

Sprint 3 不實作付款，只保留 Architecture（介面與資料結構）。

---

## 原則九：Mobile First（Android 6.5 吋基準）

所有新頁面都必須符合 Mobile First。

以 **Android 手機 6.5 吋螢幕**作為主要設計基準。

每完成一個頁面，必須自行檢查：

| # | 檢查項目 | 標準 |
|:-:|:---------|:-----|
| 1 | 按鈕是否容易點擊 | 點擊目標 ≥ 48px，間距充足 |
| 2 | 字體是否適合 50 歲以上閱讀 | 內文 ≥ 18px，對比度充足 |
| 3 | 是否可以單手完成主要操作 | 核心操作在拇指可及範圍 |
| 4 | 是否需要過多輸入文字 | 優先用選擇代替輸入 |
| 5 | 是否有明確的返回路徑 | 返回首頁 + 返回上一頁清晰可見 |

**核心精神**：如果可以減少一個操作步驟，就優先採用更簡單的流程。

任何頁面第一次使用都應該不需要教學即可理解。

---

## 原則十：Sprint 3 完成後先跑 MVP 1.0 全站體驗測試

Sprint 3 全部完成後，**不急著進入 Sprint 4**。

請先以「第一次接觸 AI、只會用手機的學員」角度，完整走一次：

1. 註冊
2. 登入
3. 進會員中心
4. 看圖片課程
5. 看影片課程
6. 使用提示詞工具
7. 報名活動
8. 登出

**只有當整個流程都順暢，才開始 Sprint 4**（訂閱、生成工具、商業案例等）。

---

## 原則九：CEO 核心原則（最高優先）「複製→貼上→成功」

> **本原則適用於所有教材、網站、電子書、課程、工作流。所有 Agent 皆須遵守。**

1. **每增加一個操作步驟，都必須有充分理由。**
2. **如果能減少一個步驟，就絕不增加一個步驟。**
3. **所有設計都以熟齡 AI 新手為中心。**
4. **目標不是教會 Prompt，而是讓學員成功。**
5. **成功率永遠高於功能數量。**
6. **「複製→貼上→成功」為最高設計原則。**

> 很多人教的是「AI 怎麼運作」，而我們教的是：「不用懂 AI，也能用 AI。」
