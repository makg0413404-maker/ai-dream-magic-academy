# AI 圓夢魔法學院 · 永久開發原則

> 本文件記錄所有不可違反的開發原則。任何 Agent（Hermes / Codex）在進行開發決策前，都必須先檢視本文件。

---

## 原則一：熟齡友善第一優先

**任何新功能都必須回答一個問題：**

> **「這個功能能不能讓熟齡學員用手機在 3 分鐘內完成？」**

若答案是否定的，該功能必須重新設計或暫緩。

### 具體標準

| 維度 | 標準 |
|:-----|:-----|
| 操作步驟 | 最多 3 個點擊完成核心任務 |
| 文字輸入 | 盡量減少，優先用選擇代替輸入 |
| 字體大小 | 內文 ≥ 18px，不可小於 14px |
| 表單欄位 | 必要欄位 ≤ 5 個 |
| 錯誤訊息 | 清楚說明如何解決，不顯示技術錯誤碼 |
| 載入時間 | 首屏 ≤ 3 秒 |

### 禁止事項

- ❌ 增加操作步驟而不說明理由
- ❌ 使用專業術語而不提供解釋
- ❌ 在小螢幕隱藏重要功能
- ❌ 要求使用者學習複雜流程

---

## 原則二：小步提交（Small Commits）

每完成一個 Task 即建立一個 Git Commit，不得累積大量修改。

---

## 原則三：每 Task 必須驗收

每個 Task 完成後必須執行：
- `npm run build`
- `npm run lint`
- TypeScript 型別檢查
- 功能測試

全部 PASS 才能進下一個 Task。

---

## 原則四：錯誤不累積

若 Build 或測試失敗，立即修復，不得帶著 Error 繼續開發。

---

## 原則五：品牌一致性

所有設計決策必須符合 Brand Bible V1.0，尤其是：
- 色彩系統（魔法藍 #4F7CFF / 魔法紫 #7C3AED / 金色 #F4C542）
- 字體系統（Noto Sans TC + Inter）
- 「AI 是工具，人才是主角」

---

## 原則六：會員中心極簡

會員中心目前只保留：
- AI 圖片教學
- AI 影片教學
- 提示詞工具
- 個人資料
- 活動報名

**不得新增工作流教學功能。**

---

## 原則七：Media 統一 Schema

`media_items` 必須支援：
- `image`（圖片）
- `youtube`（YouTube 影片）

保留 `sort_order` 欄位，未來方便首頁排序。

---

## 原則八：Payment 架構優先

Sprint 3 不實作付款，只保留 Architecture（介面與資料結構）。

---
